# o3port in Rust Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust binary `o3port` that reproduces `bench/o3_graph/o3port.py run` byte for byte (every product and `--dump`), runs families in parallel, plus a `--net-reads` product of `candidate_copies` that replaces the Python `accept_o3_candidates.py nets` step as the source of `net_reads.tsv`.

**Architecture:** A library module `src/o3port/` (one file per responsibility: statistics, BAM piles, clustering, slots and consensus, putative signals, O2 sites, the family driver) and a thin binary `src/o3port_bin.rs` (arguments, product writers, rayon over families, outputs in sorted family order). Each task ports one group of Python functions with unit tests copied from `bench/o3_graph/test_o3port.py`; Task 7 closes on byte-identity with golden Python outputs regenerated in Task 0. `candidate_copies` already builds the nets internally (`collect_nets`); Task 9 only writes them out.

**Tech Stack:** Rust 2021, noodles-bam/sam/bgzf/csi/core, rayon, anyhow, existing `rustle::genome::IndexedFasta`, `rustle::candidates::detect::minimap2*` helpers, `rustle::types::{DetHashMap, DetHashSet}`. Python 3 + pysam only for the golden side.

**Spec:** the Python port itself — `bench/o3_graph/o3port.py` (behaviour reference, 1,230 lines) and `bench/rna_allele/accept_o3_candidates.py` `def nets` (line 155); design rationale in `docs/superpowers/specs/2026-10-23-o3-strainy-isocon-design.md`. Where the plan and the Python disagree, the Python wins.

## Global Constraints

- Products byte-identical to the Python on every golden case of Task 0: `PREFIX.candidates.tsv`, `.contigs.fa`, `.clusters.tsv`, `.reads.tsv`, `.families.tsv`, `.putative.tsv`, `.putative.fa`, `.loci.tsv`, `.o2.tsv`, and `--dump` JSONL.
- Same CLI as Python: `o3port run --bam B --copies C --genome G --net N --out PREFIX [--families F1,F2] [--slot-order divergence|support] [--isocon PREFIX] [--clusterer cc|lp] [--coverage] [--semi] [--anchor] [--one-site] [--guard] [--prefer] [--no-reconstruct] [--no-clipping] [--correct] [--no-structure] [--v5-clique] [--absorb] [--isocon-rule no-pile|via-b] [--dump PATH]`, plus `--threads N` (default 4; never changes output).
- Constants verbatim: MIN_READS 2, MIN_Q 10, AS_TIE 10, ALPHA 0.01, MAX_ROUNDS 100, CLIP_BP 50, CLIP_BIN 20, MIN_SUPPORT 6, SITE_FLANK 5, CANONICAL = {GT-AG, GC-AG, AT-AC, CT-AC, CT-GC, GT-AT}; missing base qualities = 40.
- `homology()` runs `minimap2 -c --eqx -x asm20 -t 1 target query` (binary from `RUSTLE_MINIMAP2`, default `minimap2`), in a temp dir beside `--out`, removed on exit.
- Build only: `CARGO_TARGET_DIR=/mnt/linuxdisk/home/juanfraitu/rustle_target cargo build --release --bin o3port > /mnt/linuxdisk/tmp/o3port_build.log 2>&1; echo $?` (output to a file, check the exit code). Tests: `cargo test --release --lib o3port` likewise.
- Machine: heavy runs through `bash tools/rlock.sh heavy` with `RLOCK_TIMEOUT ≤ 585`, foreground, serial; goldens and big outputs under `/mnt/linuxdisk/tmp/o3port_golden/`; no `pkill -f`.
- Floats: `math.lgamma` is CPython's own Lanczos (`Modules/mathmodule.c` `m_lgamma`), not libm — port it verbatim; `exp`/`log` via Rust std (glibc). `{x:.3f}` → `format!("{:.3}")`. JSON floats in `--dump` follow Python `repr` (`1.0`, `1e-05`), see Task 7.
- Commits on branch `o3-fast`, trailer from the session; no push unless the user asks. Results go to `docs/LEDGER_O3.md` (no new .md files) and one register row.

## Review Focus

1. **Python set/dict order leaking into outputs** (iteration over `set` of read names is hash-seeded): Rust must match the *sorted* order, so Task 0 first proves the Python output is the same under two `PYTHONHASHSEED`s and fixes the Python where it is not. Test: Task 0 Step 2.
2. **Reads without base qualities, hard-clipped and reverse-strand records** (`oriented`: complement + `lead` offset): expected same observations as Python. Test: Task 2 `walk_hard_clip_reverse`.
3. **Families with an empty net, no piles, or no informative column**: still one `families.tsv` row with zeros, no other rows. Test: Task 7 `empty_family_row`.
4. **minimap2 returns an empty PAF in `homology()`** (no hit between a haplotype and the other copies): same fallback as Python (no homology, not an error). Test: Task 6 `homology_no_hit`.
5. **`--threads` changes nothing**: products from `--threads 1` and `--threads 4` byte-identical. Test: Task 8 Step 1.
